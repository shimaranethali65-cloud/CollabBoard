--------------------------------------------------------------------------------
OVERVIEW OF WORKLOAD DISTRIBUTION
--------------------------------------------------------------------------------
The entire CollabBoard system has been architected into 7 distinct, cohesive, and
well-balanced modules. Each member owns full-stack responsibilities (frontend
pages, backend controllers, routes, models, and services) ensuring that all 7
team members have an equal and independent share of the project.

Member 1 : Authentication, Authorization & User Identity Management
Member 2 : Admin Panel, Project Oversight & Approval System
Member 3 : Project Discovery, Catalog & Exploration Board
Member 4 : Project Workspace, Member Enrollment & Leadership Hierarchy
Member 5 : Task Management & Kanban Board Workflow
Member 6 : Project Status Tracking, Filtering & Personal Portfolio
Member 7 : User Profiles, Team Directory, Navigation & System Core

================================================================================
MEMBER 1: AUTHENTICATION, AUTHORIZATION & USER IDENTITY MANAGEMENT
================================================================================
Responsibilities:
- User registration and login flows with form validation and feedback
- Dual authentication architecture (Regular User login vs Admin login separation)
- Global session management, JWT creation, token storage, and persistent state
- Role-based route protection (guards for guest, authenticated user, and admin)
- Password security using bcrypt encryption and authentication middleware

Assigned Files:
1.  client/src/pages/LoginPage.tsx
    - Dedicated user login page (/login) with authentication validation
2.  client/src/pages/RegisterPage.tsx
    - User registration page (/register) with visual design assets
3.  client/src/context/AuthContext.tsx
    - React Context provider managing user state, tokens, login/logout functions
4.  client/src/components/ProtectedRoute.tsx
    - Route wrapper enforcing authentication and role permissions
5.  client/src/services/authService.ts
    - Client API calls for login, registration, admin-login, and token refresh
6.  server/src/controllers/authController.ts
    - Handlers for register, login, adminLogin, and getCurrentUser
7.  server/src/routes/authRoutes.ts
    - Express routing for /api/auth/register, /api/auth/login, /api/auth/admin-login, /api/auth/me
8.  server/src/middleware/requireAuth.ts
    - JWT token verification middleware, optionalAuth, and requireAdmin guards
9.  server/src/utils/auth.ts
    - Password hashing, bcrypt comparison, and JWT token signing/verification
10. server/src/models/User.ts
    - User model TypeScript definitions and public user serialization

MEMBER 4: PROJECT WORKSPACE, MEMBER ENROLLMENT & LEADERSHIP HIERARCHY
================================================================================
Responsibilities:
- In-depth project details workspace (/view-project)
- Self-enrollment and unenrollment system for regular users
- Automatic First-Enrolled Member leadership assignment (leaderId)
- Project Leader authority:
    * Only the designated leader can submit the project for Admin approval
    * Only the leader can transfer leadership to another enrolled member
- Auto-status progression: projects automatically transition from TODO to DOING when member quota is reached
- Relational schema modeling in Prisma for projects, members, and leaders

Assigned Files:
1.  client/src/pages/ViewProjectPage.tsx
    - Comprehensive project workspace: details, enrollment buttons, submit project, leader delegation modal
2.  client/src/services/projectService.ts (Workspace & Leader methods)
    - enrollInProject, unenrollFromProject, changeProjectLeader, getProjectById
3.  server/prisma/schema.prisma (Project & Membership models)
    - Project model, ProjectMember join table, leaderId foreign keys and relations
4.  server/src/models/project.ts
    - PopulatedProject interface, serializeProject helper, Prisma include queries
5.  server/src/controllers/projectController.ts (Enrollment & Leader functions)
    - enroll, unenroll, changeLeader, submitProject
6.  server/src/utils/projectAccess.ts
    - Permission checks: assertMember, assertLeader, assertOwner, isLeader

MEMBER 6: PROJECT STATUS TRACKING, FILTERING & PERSONAL PORTFOLIO
================================================================================
Responsibilities:
- Three-phase project lifecycle tracking board (/task-status):
    * TODO: Projects actively recruiting (waiting for required members to fill)
    * DOING: Quota filled, active development ongoing
    * DONE: Leader submitted & Admin approved
- Personal projects portfolio (/my-projects) showing only projects the user is enrolled in
- Progress visualization and quick-action project submission for leaders

Assigned Files:
1.  client/src/pages/TaskStatusPage.tsx
    - Tri-column lifecycle tracking board (/task-status) separating TODO, DOING, and DONE projects
2.  client/src/pages/MyProjectsPage.tsx

3.  client/src/services/projectService.ts (Query & Status methods)
    - getMyProjects, submitProject
4.  server/src/controllers/projectController.ts (Listing & Status functions)
    - getMyProjects, getProjects (with status filtering), withProgress calculation helper
5.  server/src/utils/validators.ts
    - Status validation (TODO, DOING, SUBMITTED, DONE, CLOSED) and priority rules
